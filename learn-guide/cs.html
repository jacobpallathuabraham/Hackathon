Sorting race

Open the live experience

Kind
Visualizer (interactive)

The question it starts from
Bubble, insertion, merge, quick: watch four algorithms race and count every comparison.
What the model simplifies
40 values; counts are exact for these implementations.

Introduction

Watch algorithms sort the same bars. Each comparison lights up yellow and each swap or write red. Choose an algorithm, the starting order and the speed, and compare how many comparisons each needs.

Predict first

To sort 40 random values, which needs fewer comparisons?

  1. Bubble sort
  2. Merge sort
  3. They need the same
  4. It depends only on luck

What to do

Run bubble sort then merge sort on the same random data, and compare the counts. Then try both on data that is already nearly sorted.

Controls

  • Insertion sort — button
  • Merge sort — button
  • Quicksort — button

Start

  • Random — button
  • Nearly sorted — button
  • Reversed — button
  • Steps per frame — slider (1 to 60, step 1)
  • Sort ▸ — button
  • New data — button

The explanation

Simple sorts like bubble and insertion compare neighbouring items, so on random data they need roughly n²/2 comparisons — 780 for 40 items. Merge sort splits the list in halves, sorts each and merges them, needing about n log₂ n comparisons — around 200. On data that is already nearly sorted, insertion sort is very fast (few moves needed), which is why the best algorithm depends on the data.

Apply it

  1. mcq Doubling the number of items roughly multiplies bubble sort’s work by…

    1. 2
    2. 4
    3. 8
    4. no change
    Answer and explanation

    Answer: 4

    n² growth.

  2. mcq Merge sort works by…

    1. swapping neighbours
    2. dividing, sorting halves and merging
    3. guessing
    4. picking the largest each time
    Answer and explanation

    Answer: dividing, sorting halves and merging

    Divide and conquer.

Summary

  • Bubble/insertion: ~n² comparisons on random data.
  • Merge sort, quicksort: ~n log n.
  • The best choice depends on the data.

The explanation

Each bit is worth a power of two: from the right, 1, 2, 4, 8, 16, 32, 64, 128. 01000001 = 64 + 1 = 65, which ASCII uses for “A” (97 is “a”: lowercase letters are 32 higher). Eight bits hold 2⁸ = 256 values, 0 to 255. Hexadecimal groups 4 bits per digit (65 = 0x41). Adding 1 to 255 in a single byte wraps round to 0 — an overflow.

    1. 10
    2. 1010
    3. 5
    4. 12
    Answer and explanation

    Answer: 10

    8 + 2.

  2. mcq How many different values can 8 bits represent?

    1. 8
    2. 16
    3. 255
    4. 256
    Answer and explanation

    Answer: 256

    2⁸.

Summary

  • Place values are powers of two.
  • One byte: 0–255; hex uses 4 bits per digit.
  • Text is stored as numbers (ASCII/Unicode); overflow wraps round.

The explanation

Logic gates combine binary signals. AND gives 1 only if both inputs are 1; OR if at least one is; XOR if exactly one is; NAND and NOR are the opposites of AND and OR. Chaining gates builds any function: (A AND B) AND C is 1 only for 1,1,1; (A XOR B) XOR C is 1 when an odd number of inputs are 1 — the basis of parity checks and of adding binary numbers. Every circuit in a processor is built from such gates.

Path finder

Draw a maze; race breadth-first search against A* to the goal.
What the model simplifies
4-way moves on a grid; Manhattan heuristic.

Introduction

Draw walls on the grid (click or drag), then let a search algorithm find a path from the green start to the red goal. Compare breadth-first search, which spreads out evenly, with A*, which uses a guess of the distance to head towards the goal.

Predict first

Compared with breadth-first search, A* usually…

  1. finds a longer path
  2. explores fewer cells to find an equally short path
  3. never finds a path
  4. explores every cell

What to do

Run BFS, note the cells explored. Run A* on the same maze. Then draw a wall that blocks the direct route and compare again.

Controls

  • Run BFS — button
  • Run A* — button
  • Example walls — button
  • Clear walls — button

Every experience also has the step buttons Hook · Predict · Explore · Observe · Explain · Apply · Connect, and Pause and Reset for the model. Above, each control is listed with the label the student sees. Moving a control changes the live model and its readout.

The explanation

Breadth-first search explores cells in rings of increasing distance, so it always finds a shortest path, but it explores in every direction. A* ranks cells by distance so far plus an estimate of the distance remaining (here the Manhattan distance). Because the estimate never overestimates, A* still finds a shortest path but usually explores far fewer cells. Sat-navs and game characters use variations of these ideas.

Apply it

  1. mcq BFS guarantees the shortest path on a grid with equal step costs because…

    1. it is random
    2. it explores in order of distance from the start
    3. it goes straight
    4. it uses a heuristic
    Answer and explanation

    Answer: it explores in order of distance from the start

    Rings of increasing distance.

  2. mcq A*’s heuristic should…

    1. overestimate
    2. never overestimate the remaining distance
    3. be random
    4. be zero always
    Answer and explanation

    Answer: never overestimate the remaining distance

    An admissible heuristic keeps paths optimal.

Summary

  • BFS: explores evenly, shortest path guaranteed.
  • A*: cost so far + estimated cost to go.
  • Good heuristics cut the search.

3.1 What is an algorithm?

An algorithm is a precise, step-by-step recipe for solving a problem. Before writing any code, programmers often sketch it in pseudocode: plain-language steps such as “for each student, add their mark to the total”. Pseudocode lets you check the logic without worrying about syntax.

Most algorithms combine three building blocks: sequence (do steps in order), selection (make a choice with a condition, such as “if the mark is at least 50”), and repetition. Repetition is handled by a loop, which runs the same steps again and again; each pass through it is called an iteration.

3.2 Loops in practice

A variable is a named box that stores a value, such as total = 0. A typical loop updates a variable on every iteration: “for each mark in the list, total = total + mark”. When the loop ends, total holds the sum. A loop must always have a way to stop; otherwise it becomes an infinite loop and the program never finishes.

Errors in logic are called bugs, and finding them is debugging. A powerful habit is to trace the loop by hand: write down the value of each variable after every iteration for a small example. Most bugs appear within the first two or three passes.

3.3 Searching smarter

Linear search checks items one by one until it finds the target. It works on any list, but for a list of one million names it may need one million checks. Binary search is much faster on a sorted list: it checks the middle item, discards the half that cannot contain the target, and repeats.

Because it halves the list each time, binary search needs only about twenty checks for a million items. Computer scientists describe this growth with time complexity: linear search grows in step with the list, while binary search grows only logarithmically.
